# 《重生之我在凌晨三点奶娃娃》设计文档

- 日期：2026-08-14
- 状态：已获用户逐节确认（剧情结构 / 系统架构 / 视觉与素材 / 边界与验证）
- 项目目录：`reborn-3am/`（位于工作区内，独立 git 仓库）

## 1. 背景与目标

为 momcozy 吸奶器产品线内部使用：让部门男性工程师通过一款 6–8 分钟的网页互动剧情游戏，代入女性用户视角，体验真实产品使用痛点，从而促进产品改进讨论。

- 受众：中国工程师（会议上投屏集体玩 / 个人碎片时间玩）
- 语言：全中文
- 形式：浏览器网页游戏（Vite + React + TypeScript + Tailwind），Kimi Work 预览链接交付
- 单次体验时长：6–8 分钟，约 14–17 个交互节点

## 2. 需求定稿

| 决策项 | 定稿 |
|---|---|
| 叙事视角 | 丈夫视角 + 梦境灵魂互换（前半段旁观，中段入梦成为妻子） |
| 游戏名 | 《重生之我在凌晨三点奶娃娃》，副标题"—— 一位工程师的梦" |
| 角色 | 陈俊生（丈夫，33 岁，结构工程师）、罗子君（妻子，产后 4 个月）、凌玲（彩蛋，深夜来电的同事） |
| 痛点场景 | A 喇叭罩尺寸不合适 · B 配件拆洗地狱 · C 噪音焦虑 · F 凌晨孤独 |
| 结局基调 | 克制余味型：惊醒 → 凝视背影 → 真实数据卡逐行浮现；预留"讨论引导页"开关 |
| 互换机制 | 梦境：凌晨 3 点闹钟后丈夫睡去，梦中成为妻子；梦醒收束 |

### 2.1 凌玲彩蛋设计规则

- 插入位置：第一幕，节点 1 之后
- 形式：QTE 时机微交互——手机震动，屏幕显示"凌玲"来电，玩家须在妻子翻身前点下"挂断"
- 两种结果只影响当幕文案，不影响主线与结局
- **只出现一次，不解释**（《我的前半生》梗，懂的人会心一笑，不懂不影响体验）
- 彩蛋不进第三幕结局，避免破坏收束情绪

## 3. 剧情结构（三幕）

### 第一幕 · 丈夫（夜，约 1.5 分钟）

| 节点 ID | 类型 | 内容 |
|---|---|---|
| a1-n1 | narration | 23:00，陈俊生加班回家。妻子罗子君已睡。床头放着吸奶器，水盆里泡着拆开的零件 |
| a1-n2 | choice | 看到水盆，心里嘟囔。选项 1"假装没看见，躺床上直接睡觉"（feedback：透着不理解）；选项 2"帮妻子认认真真洗干净每个零件，到凌晨 1 点才睡"（feedback：**"他洗完 6 个零件，颇有成就感地睡了。他不知道，这只是她每天的六分之一。"**） |
| a1-n3 | qte | 【彩蛋】手机震动，"凌玲"来电。限时点击"挂断"。成功："你赶在子君翻身前挂断了。呼——"；失败：子君迷迷糊糊问"谁啊，这么晚"，你说"……打错了"，她翻身又睡 |
| a1-n4 | choice | 凌晨 3:00 闹钟响，妻子轻手轻脚起床。选项 1"被惊醒，但太疲惫，说'你自己弄吧…'"；选项 2"什么都不说，继续装睡" |
| a1-n5 | narration | 沉沉睡去。画面渐黑，浮现一行字：**"然后，他做了一个梦。"** |

### 第二幕 · 梦中，你成为了她（凌晨→白天→深夜，约 4.5 分钟）

核心机制：**无力感是被设计出来的**——玩家试图寻找"轻松的选项"，但每个选项都引向不适。选项不改变主线（控制 demo 复杂度），只改变反馈文案与状态值（疲惫值 / 疼痛值）。

| 场景 | 痛点 | 节点 | 机制设计 |
|---|---|---|---|
| ① 凌晨 3 点床尾 | F 孤独 + C 噪音 | a2-s1-n1（narration：你成了罗子君，独自坐在床尾）；a2-s1-n2（choice） | 静音档吸不干净 vs 标准档吵醒宝宝，**两个选项都是错**：选标准档→宝宝哭了，去哄，回来重泵，更累；选静音档→30 分钟后只有 60ml，奶量焦虑 |
| ② 清晨第一次泵奶 | A 喇叭罩尺寸 | a2-s2-n1（narration：针扎般疼痛）；a2-s2-n2（choice） | 选项 1 忍着继续（疼痛值↑，奶更少）；选项 2 停下翻说明书→发现要量尺寸，家里没有合适法兰，**"配件到货要三天"——这三天只能继续疼** |
| ③ 白天的循环 | B 拆洗地狱 | a2-s3-n1 / n2 / n3（三个连续节点） | 重复机制：拆 6 个零件→洗→消毒→晾干，**让玩家亲手点完三轮**；第三轮时浮现："这就烦了？她每天要重复 6 次。" |
| ④ 深夜收束 | F 情感顶点 | a2-s4-n1（narration） | 一天的尽头，极度疲惫，手指在屏幕上设好明天 3:00 的闹钟。黑屏 |

### 第三幕 · 惊醒（克制余味结局，约 1 分钟）

| 节点 ID | 类型 | 内容 |
|---|---|---|
| a3-n1 | narration | 猛然惊醒，凌晨 3:04。床尾台灯下，是妻子沉默的背影 |
| a3-n2 | choice | 唯一选项："轻轻走过去"——走过去，坐下，不说话 |
| a3-n3 | datacard | 黑屏，数据卡逐行浮现（见 3.1） |
| a3-n4 | end | 最后一行字 + （开关开启时）讨论引导页 |

#### 3.1 数据卡文案（逐行浮现）

1. 哺乳期妈妈平均每 2–3 小时泵一次奶，每天 6–8 次
2. 一次拆洗 6 个零件 × 每天 6 次 = 36 次
3. 53% 的用户把静音列为购买吸奶器的第一指标
4. 喇叭罩尺寸不合适是疼痛的首要原因，多数妈妈不知道需要测量
5. **她经历的每一天，对他只是一场梦。**

备注：第 3 条取自工作区《吸奶器行业洞察报告_2026.md》（Market Growth Reports 2026-07，估计值口径）；第 1/2/4 条为通用哺乳常识与产品使用事实。

#### 3.2 讨论引导页（开关 `showDiscussion`，默认关闭）

1. 这四个痛点里，哪些是我们明天就能动手改的？
2. 玩之前，你猜对了一位妈妈每天要拆洗几次吗？
3. 如果你是罗子君，你最想对我们产品说的一句话是什么？

## 4. 游戏机制

- **主交互**：阅读 + 选项推进。选项点击后短暂禁用防连点，附 1 行反馈文案再进入下一节点
- **状态值**：`fatigue`（疲惫）、`pain`（疼痛），由选项 effects 累积
- **状态可视化走"无形化"路线**：不显示数值条——疲惫值越高，画面暗角越重、文字呼吸越慢；疼痛值在相关节点触发文字微颤。电影感优先于游戏感
- **QTE**：凌玲来电为全游戏唯一时机交互，限时约 2.5 秒
- **重复机制**：场景 ③ 连续三次相同的"拆洗"点击，刻意制造烦躁，随后点题
- 页面刷新 → 回标题页（demo 无存档）

### 5.1 剧本数据 Schema（TypeScript）

```ts
type StatKey = 'fatigue' | 'pain';

interface Choice {
  label: string;
  feedback?: string;   // 选择后先展示的一行反馈
  effects?: Partial<Record<StatKey, number>>;
  next: string;        // 目标节点 id
}

type NodeType = 'narration' | 'choice' | 'qte' | 'datacard' | 'end';

interface GameNode {
  id: string;
  scene: string;       // 场景分组 → 背景/插画映射
  type: NodeType;
  text: string;        // 主文案，\n 分段
  speaker?: string;
  choices?: Choice[];  // type = choice
  qte?: { timeoutMs: number; buttonLabel: string; successNext: string; failNext: string };
  next?: string;       // type = narration 的默认推进
}
```

### 5.2 校验脚本规则（`validate-script.ts`）

- 所有 `next` / `successNext` / `failNext` 指向存在的节点
- 无不可达节点、无死路（除 `end` 类型外每个节点都有出口）
- 每个 `scene` 有对应的背景映射
- 从起始节点 DFS 可达结局节点

## 6. 视觉与素材

- **视觉方向**：电影感、暗色调、大字排版；靠字体 / 留白 / 节奏取胜，不堆砌动效
- **参照流程**：动手前先经 musepool 检索设计参照，配色与字体以参照为准，不凭空定色
- **插画**：image_generation 生成 8 张——标题、深夜卧室、凌晨床尾、清晨浴室、白天洗零件、深夜设闹钟、惊醒背影、数据卡底图；统一 prompt 模板锁画风
- **音效（可选，可整体缺省）**：闹钟、婴儿哭、泵奶器低鸣，audio_generation 生成；遵守浏览器自动播放限制，首次点击后才启用；无声可完整通关
- **中文排版纪律**：中文不使用斜体；字体栈显式包含中文字体

## 7. 边界与验证

- 16:9 投屏优先，手机竖屏兼容（响应式）
- 防连点：选项点击后禁用 + 转场动画
- 验收 = 校验脚本通过 + 全流程试玩 checklist：每条选项分支走一遍，含凌玲彩蛋挂断成功/失败两种结果

## 8. 非目标（YAGNI）

- 无存档 / 读档；无多结局；无用户系统；无后端
- 不做英文版
- 音效为可选项，缺失不阻塞交付

## 9. 验收标准

1. 从标题页到结局全流程可走通，所有选项分支可达且无死路
2. 四个痛点场景与三幕结构与本文件第 3 节一致
3. 凌玲彩蛋两种结果均可触发
4. 结局数据卡按 3.1 文案逐行呈现
5. `npm run dev` 可启动，16:9 与手机竖屏布局正常
6. `validate-script` 校验通过
